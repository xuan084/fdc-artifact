# Lock v8 附录：eval 结果汇总（2026-10-04）

## 结论先行

- **块 A（确认性，X5 RetailHero 未触碰的 eval 半边）判定为 `positive_result_achieved`。** 判定由锁定的判定函数 `v8_analysis.decide_block_a` 原样得出，四个分量全部通过：
  - **F（矩形，优效）**：UB*_F = 0.368（RECT-ck-HG 与 RECT-ck-HG-live 相同），低于 0.60；对调好的 HC-WoR*（nstar, 0.6, Neyman 计划）为 0.367；
  - **G（联合证书，非劣）**：UB*_G = 1.011（PJC-local*，无重置成员），低于 1.05；对 PJC-menu* 为 0.978；
  - FDC-BF 在 ε = 0.02 的 200 条新流上 0 条错误流（CP 95% UB 0.0149）；
  - replica 两个任务都通过，跨任务 R2b 也通过。
- **效应大小（N80_pen，ε = 0.02）。** FDC-BF 比三个矩形快约 2.75 倍（比值 0.362–0.364，200/200 条流更快）。
- **与 PJC 的关系必须如实写。**
  - 对无重置的 PJC-local*，点估计为 1.003 [0.994, 1.012]：两者**打平**（90% 的流相同，4% 更快，6% 更慢），FDC-BF **不比它快**；
  - 对自适应的 PJC-menu*，FDC-BF 快约 3%（0.968，UB 0.978）。但 PJC-menu* 在 200 条流上都选了 50/50 菜单项（路径 (1,)），它的劣势来自菜单并集的 β 代价，而不是自适应设计本身；
  - 因此注册结论只支持"比矩形快"和"不比相位自适应联合证书慢 5% 以上"，**不支持**"比 PJC 快"。速度收益来自联合（方向级）聚合本身，而不是 FDC-BF 特定的分配方式。
- **块 B（CR12，描述）与块 C（CR9 v7 流，描述、事后）给出同样的图景。**
  - 对矩形的比值：CR12 上约 0.55，CR9 上的 matched Bennett 矩形约 0.50；
  - 对 PJC-local* 打平（1.00），对 PJC-menu* 为 0.95–0.98；
  - FDC-BF 在 CR9 v7 流上的重跑与 v7 封存行 200/200 逐字段相同。
- **plug-in。** B5（渐近方法）在 X5 上比 FDC-BF 快约 3.7 倍，在 X5 上 0 条错误流；在 CR9 上快约 2.2 倍，但有 2/200 条错误流。论文须写"plug-in 更快但无保证"。
- **边界。** 本判定不改变 v5、v6、v7 的任何判定。
