**1. FDC-DP validity: yes, with the stated assumptions.**

The correct main event family is `(q, candidate answer pi, k)`, where each event compares that answer with the fixed true optimum for q. It is not a union over all ordered policy pairs. The optimum depends on the fixed population, not replay randomness. On the simultaneous event, the observed centre selects one of these already-covered candidate answers. The proof at `plan/fdc_dp_theory.md:131` correctly makes this distinction.

The counting recurrence and gcd reduction are correct (`exp/code/dsswm/baselines/fdc_dp.py:112`, `:123`, `:148`). Python integers preserve the policy count; taking its logarithm afterward is appropriate. Overlapping policy classes across budgets can be counted separately, since q is part of the index. The variance ledger uses **SA**, not a hard-coded original segment count: two tails times SA cells times K checkpoints, with alpha = delta_var/(2SAK) (`fdc_dp.py:156`, `:490`). Running intersections preserve coverage on the simultaneous box event.

There is one centre-independent lambda grid per checkpoint in `fdc_dp.py:533`. No additional lambda union is necessary: on E_var every evaluated objective dominates the deterministic true-MGF Chernoff infimum, so its data-dependent minimum also dominates that infimum. This is not conditioning a tail bound on an estimated variance. Preserve the **strict-tail** statement P(Y > t*) <= exp(-beta), using the limiting argument from the inherited theorem when the infimum is unattained. The complement of the event written in DP-1 is indeed strict.

Conditioning must mean the arrival/planned-arm/reselection schedule, excluding within-cell outcome permutations, as defined in `plan/theory/fdc_theorem.md:37`. It also conditions on the already-constructed population, segmentation, costs, and weights. Under that interpretation the required independent WoR cells are justified.

**2. Scheme (b): exact when completed, for the same centre, columns, and lambda set.**

For any subtree, min_j max_pi C_j(pi) bounds max_pi min_j C_j(pi) from above. The suffix DP implements the residual capacity and the requirement of at least one departure from the centre (`fdc_dp.py:231`). Thus pruning at UB <= epsilon is sound. At a feasible non-centre leaf the bound becomes the actual column minimum. Without a cap, decision mode is exact; max mode computes the exact maximum in real arithmetic. Floating-point tests support the advertised numerical tolerance, not a formal interval-arithmetic guarantee.

The dominance rule at `fdc_dp.py:284` is also sound. Replacing dropped options by the centre weakly decreases cost and weakly increases every column. If replacement removes every difference, the original policy's column minimum was at most min_j const_j <= epsilon, so it could not have been a violator. Pruning is appropriately disabled in max mode. The exact column has constant zero, so for nonnegative epsilon the constant proviso is satisfied even independently of the grid endpoint.

The node-cap fallback is safe (`fdc_dp.py:343`, `:571`): incomplete search cannot produce certification. It can lose power, so the capped algorithm is **not an unconditional iff implementation** of FDC-BF. The code even reports a cap hit when the final permitted iteration emptied the stack; that is conservative. My forced-cap example returned `node_limit`, while the uncapped search and enumeration certified.

Two qualifications require correction: the wrong centre prevents whole-method equivalence to the stated FDC-BF rule (blocking fix B1), and `FDCDP.certify_with` returns U_a even after branch-and-bound has proved certification with U_a > epsilon (`fdc_dp.py:563`, `:573`, `:576`). The boolean can be correct while the returned field is neither the exact U nor a numerical witness of U <= epsilon. Label and expose these quantities honestly (B3). A global grid spanning native FDC-BF's grid ranges does not contain the native grid points; equality with native per-direction grids is neither proved nor required.

**3. Scheme (a): valid.**

The max-min inequality has the correct direction. The forward DP includes the difference flag and optimizes each additive column over the same budget class (`fdc_dp.py:209`, `:253`). A posteriori selection of a common column is covered by the same deterministic-infimum argument. Consequently U_a <= epsilon suffices, although U_a can exceed the exact certificate. No additional delta allocation is required to use (a) before (b).

**4. RECT-BF-DP: a valid and fair matched aggregation rival, subject to B1.**

The inherited ledger is exactly 2SAK one-sided events at beta_C = log(2SAK/0.045), plus the separate 0.005 box event (`exp/code/dsswm/baselines/pjc_bf.py:368`). The implementation uses the same Bennett-FPC inequality, HG variance boxes, delta split, and 50/50 design. It additionally intersects the cell intervals with logical finite-pool bounds, the paid-for box, and previous intervals (`pjc_bf.py:382`; `rect_dp.py:65`). These strengthen the rival.

For a fixed centre, common policy coordinates cancel exactly. Each changed coordinate contributes w_s(hi_challenger - lo_centre). Maximizing this sum by the one-column knapsack DP is the exact worst-case rectangle gap, including the outer maximum with zero (`exp/code/dsswm/baselines/rect_dp.py:44`). No Q or policy-count penalty belongs in this rectangle ledger. The rival is not weakened by enumerating only short changes or by an approximate challenger search.

It is fair for the stated **matched aggregation** comparison. It is not established as the strongest possible rectangle: neither optimized centre selection nor every valid cell interval is compared. In particular, a direct exact-HG checkpoint rectangle spending 0.05 on its cell intervals is a legitimate additional comparator. That omission does not invalidate this matched experiment. Use “best of the two specified rectangle implementations,” not an unrestricted “best valid rectangle” claim. Broader best-method claims require broader baseline development before lock.

**5. TU extension: yes for the non-hybrid implementation under a frozen schedule.**

Lemma TU applies to each fixed optimum-versus-answer coefficient vector. With the reverse filtration and nonempty touched cells, the exponential process has the required reversed-time submartingale maximal bound. Union over `(q, pi, block)` gives the same ledger. The centre may change at every monitoring time because every possible answer is covered.

`FDCDPTimeUniform` freezes counts, boxes, lambda grid, cell MGF tables, and deterministic-cell flags at block points, while recomputing empirical differences from current observations (`fdc_dp.py:617`, `:631`). This matches the proof. A cell empty at a block must retain infinite directional width until a later block, even if it is subsequently sampled. Do not refresh HG inversions at arbitrary monitoring times without charging for those inversions. The inherited TU rectangle correctly uses frozen radii with current means and the block's fixed-mean box.

The supplied TU test checks equality only on the block grid (`test_fdc_dp.py:313`); it does not test off-block operation. Before including dense monitoring in lock v10, add off-block comparisons against same-grid enumeration with changing centres and empty-at-block cells. Hybrid TU explicitly raises `NotImplementedError` off-grid (`fdc_dp.py:634`); it must remain excluded from that claim. None of this upgrades the guarantee to outcome-adaptive allocation.

**6. Data layer: no replay-outcome leakage found in the reviewed path.**

The model mask depends only on arm and a fixed RNG seed.
