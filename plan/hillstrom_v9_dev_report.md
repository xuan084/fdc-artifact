## 0. 先回答主会话的事实问题：τ_R 是否等于整表读完

**是。**

## 1. 3 臂支持（任务 2）

审计结论：方向系数对一般 A 本来就成立。
- `fdc_bet.direction_widths` 在 π'(s) ≠ π̂(s) 的每个段上只碰两个单元：挑战者单元 (s, π'(s)) 系数为 −w_s，中心单元 (s, π̂(s)) 系数为 +w_s，第三个臂系数为 0。
- A = 3 时这两个单元仍是不同的池，所以在给定日程的条件下，各单元的超几何和相互独立，FDC-bet-1 的 Chernoff 论证原样适用。
- 并集计数（Σ_q |Π_{B_q}| × K；方差盒按 S·A·K 计）直接从 ctx 读出，对任意 A 都对。

唯一的 A = 2 限制是 `FDCBet.setup` / `PJCBF.setup` 里的检查，以及"0.5 对照份额"这一设计约定。新文件 `multiarm_v9.py` 补上了这部分：

- `RectCkBFA`：匹配的 Bennett 矩形，与 FDC-BF 同设计。
- `make_plan_rect` / `make_plan_hc`：对手的冻结计划网格 PLAN_TAGS_A3 = {bal, 0.2, 0.4, 0.5, 0.6, ney, ney23}，数字为对照份额，其余两臂均分。

RECT-ck-HG、HC-WoR 与 runner 本身没有 A 限制。

## 2. 层设计（任务 3）

### 2.1 切分、分段、问题族

- **切分**：按源行号哈希。行 i 属于 dev 当且仅当 sha256("ds-swm/v9/hillstrom/2026-10-04:i") 的前 64 位 / 2⁶⁴ < 0.5。dev 32,119 行（三臂 10,716 / 10,746 / 10,657），eval 31,881 行。dev 行号列表的 sha256 为 `e208e291…`。
- **eval 访问**：只有通过 `dsswm.stats.prereg_v9.addendum_gate` 且任务前缀为 `v9c_full` 才放行。该模块锁前不存在，因此锁前读取必然失败（已测）。
- **分段**：只用特征，切点取自全表协变量。cat3 = mens-only / womens-only / both。S = 6 的候选为 CN6 / CR6 / CC6 / CZ6，即 cat3 分别乘 newbie、recency(≤5)、channel(Web)、zip(Urban)。规则 B 另加 S = 4 的 cat2 × 同四个特征（cat2 = mens-only / 有 womens 史），以及 S = 3 的 cat3。
- **问题族**：每臂邮件成本 κ（不发邮件成本为 0），预算 B 取 0.10, 0.15, …, 0.80，共 15 题，12/15 停止。成本族有三种：
  - F1 = (0, 1, 1)；
  - F3 = (0, 1.5, 1)，即 r4 的 HR 成本档 C2，属于继承而非在 v9 数据上选择；
  - F2 = (0, 1, 0.5)，womens 邮件半价，没有先例。
- **非平凡**：在 dev 上，三个简单策略（池化贪心、按段大小发 mens、按段大小发 womens）的真实 regret 都 > ε。
- **结局**：用 visit。conversion 在任何候选上都没有落在 10–13 窗口里的 ε，只有 CC6/F1 在 ε = 0.001 处恰好达到 11，在 3 万行上无法认证（见 `design.json`）。

### 2.2 设计如何选出（修订过程全部披露）

1. **规则 v1（任何认证运行之前写下）**：只用 F1，取让 10–13 题非平凡的最大 ε，选出 CN6 / ε = 0.003。在 dev 种子 900 上，FDC-BF 与 RECT-ck-HG 都只在 τ_R 才达到 12/15（FDC-BF 第 12 小的 U 在 0.83 τ 时为 0.008），因此 v1 作废，记录在 `design_rule_v1.json`。
2. **规则 v2（设计 A）**：成本族按 F1 > F3 > F2 的优先级，并加可行性条件："FDC-BF 或 RECT-ck-HG[bal] 至少有一个在 900–909 中 ≥ 8 条流上于 τ_R 前达到 12/15"。结果：F1 全部不可行；F3 中 CR6 与 CC6 的 ε_hi 都是 0.0075，CR6 非平凡题更多（11 vs 10）。**设计 A = CR6 / F3 / visit / ε = 0.0075，11/15 非平凡。** 可行性只由 FDC-BF 一方满足，RECT 0/10。
3. **规则 B（设计 B）**：应主会话要求，在任何设计 B 运行之前写入 runner 文档串。
   - 候选：9 种分段 × 3 个成本族，ε 网格 0.0025–0.03；
   - 可容许条件：10–13 题非平凡，且未调参参照 RECT-ck-HG[bal] 在 τ_R 前最后一个检查点（k = 18）认证题数的中位数 ≥ 10（种子 900–909）；
   - 选择顺序：S 最大优先，然后成本族优先级，然后取最小的可容许 ε。

   可容许的只有三个，全部在 F2 下：CZ6 / F2（ε 0.0125）、DZ4 / F2（ε 0.01）、C3 / F2（ε 0.0025）。F1 与 F3 下没有一个候选同时满足两条。**设计 B = CZ6 / F2 / visit / ε = 0.0125，13/15 非平凡。**

**设计 B 的代价：** 它依赖 womens 邮件半价，这个成本没有出处，是三个成本族中优先级最低的；在 F1、F3 下 Hillstrom 的 dev 半边不存在"对手能认证、同时又非平凡"的设计。这一点必须在锁和论文里写明。

- CZ6 的 6 个段为 mens_only / womens_only / both，各分非 urban / urban，dev 权重 0.271 / 0.181 / 0.269 / 0.179 / 0.059 / 0.041，最小池 432 行。
- 非平凡题数随 ε 的变化：0.01 → 13，0.0125 → 13，0.015 → 9。
